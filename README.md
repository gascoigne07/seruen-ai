# Seruen AI

**Куда сходить в Астане, если есть 45 минут?** Seruen AI подбирает до трёх мест рядом,
объясняет выбор и предлагает занятие. Когда хватает времени, он собирает пеший маршрут
на две–три остановки. Пользователь видит источник, часы работы и ограничения данных.

Хакатон «Build with AI», кейс №1 НИЦ Smart City. «Серуен» по-казахски означает прогулку.

Приложение рассчитано на жителей с коротким свободным промежутком, туристов и семьи.
Основные сценарии — прогулка, место для работы, выход с ребёнком и ночная идея.
Польза прототипа: быстро сузить выбор и показать основания рекомендации, ограничения
и примерное время. Это не бронирование и не навигатор по пешеходной сети.

[Соответствие брифу, риски и развитие](docs/REQUIREMENTS.md).

## Запуск

Проверенная среда: Python 3.13. Готовый датасет уже лежит в `data/`.

```bash
cd seruen-ai
make venv       # установка зависимостей, нужен интернет
make check      # офлайн-тесты, линтер, проверка датасета
make run        # http://localhost:8501
```

Если `python3.13` установлен под другим именем: `make venv PYTHON=/путь/к/python3.13`.
При готовой `.venv` достаточно `make run`. На Mac можно также дважды нажать
`start.command`: он запустит приложение и при необходимости создаст окружение.

Без серверных ключей приложение использует локальный подбор известных мест. Посетителю достаточно
выбрать контекст прогулки и отправить запрос: вход, ключи и выбор модели не нужны.
Погода выключена. Подложка карты CARTO требует интернета, а расчёт рекомендаций от неё
не зависит. Для полностью офлайн-проверки используйте CLI:

```bash
.venv/bin/python -m seruen.cli --preset mega \
  --query "Я у Mega Silk Way, хочу погулять 45 минут" \
  --demo --no-weather --now "2026-10-19 15:00"
```

Точку старта можно выбрать в интерфейсе, задать координатами или назвать в запросе:
например, «я вот в центральном парке. куда могу отсюда пойти». При подключённом OpenAI
модель сначала выделяет название текущего места. Координаты она не придумывает:
приложение проверяет название по локальным POI, проверенным ориентирам и, если нужно,
через Photon в пределах Астаны. Для Центрального парка используется точка из
[официального городского туристического источника](https://visitastana.kz/ru/about-city/what-to-see/tsentralnyy-park/).

Если совпадений несколько, пользователь выбирает место и подтверждает старт. Если место
не найдено, геосервис недоступен или старт не указан, приложение просит уточнение.
Байтерек автоматически не подставляется. В локальном режиме доступны известные ориентиры
и ручная точка, без сетевого определения места. Ручной выбор имеет приоритет.

Photon получает только выделенное название или адрес, а не весь запрос. Это поиск
по картографическим данным с неполным покрытием, а не обещание найти любой адрес города.
Показанная точка может быть центром территории; это не GPS и не проверенный вход.
Проверьте старт перед прогулкой. Название старта отделяется от пожелания: «у Ботанического
сада, хочу кафе» ищет кафе от сада. «Около двух часов» означает время, а не адрес.
В ответе доступны русский, английский и казахский языки.

«Обновить подборку» повторяет запрос с текущими условиями и может снова обратиться к
модели. «Скачать подборку» сохраняет TXT с местами, временем и источниками без нового
вызова модели. Исходный запрос и точные координаты старта в файл не входят.

## Единое подключение ИИ для посетителей

Владелец один раз настраивает модель на сервере. Все посетители используют это
подключение: в публичном интерфейсе нет аккаунтов, ключей или выбора провайдера.

### Настройка владельцем

1. Откройте `.env` в папке проекта. Если файла ещё нет, создайте его по `.env.example`.
   Существующий файл не перезаписывайте. Ключ хранится только на сервере; не вставляйте
   его в чат, браузерные формы, запись экрана или репозиторий.
2. Задайте `SERUEN_PROVIDER=openai` и свой `OPENAI_API_KEY`.
3. Выполните `make models`: команда запрашивает каталог OpenAI API без генерации ответа.
   Выберите доступную текстовую модель с поддержкой Responses API и structured outputs
   и задайте её точный идентификатор в `OPENAI_MODEL`. Каталог может включать модели,
   не подходящие для этого конвейера; автоматического выбора нет.
4. Оставьте `SERUEN_DEMO=0` и перезапустите приложение через `make run`.
5. Отправьте тестовый запрос. В панели «Какие данные использованы» режим `openai`
   подтверждает принятый ответ модели. `retrieval-template` означает локальный ответ.
   Посетитель видит общее пояснение; техническую причину владелец смотрит в CLI с `--json`.

Пример структуры настройки, значения ключа и модели владелец заполняет самостоятельно:

```dotenv
SERUEN_PROVIDER=openai
OPENAI_API_KEY=
OPENAI_MODEL=
SERUEN_DEMO=0
```

Если выбранная модель поддерживает настройку объёма рассуждений, владелец может
задать `OPENAI_REASONING_EFFORT=low`, чтобы сократить время ответа. Пустое значение
сохраняет настройку модели по умолчанию. После изменения перезапустите сервер.

В CLI используются те же серверные настройки. При необходимости владелец может
переопределить модель конкретного запуска:

```bash
.venv/bin/python -m seruen.cli --provider openai \
  --model "<идентификатор доступной API-модели>" \
  --preset mega --query "Хочу погулять 45 минут" --no-weather
```

`--model` необязателен, если заполнен `OPENAI_MODEL`. После настройки владельцем проверен реальный ответ
`gpt-6-luna`: HTTP 200, `completed`, режим `openai`, одна принятая рекомендация из двух
кандидатов, без fallback. Это результат конкретного вызова, а не гарантия будущей
доступности или модель по умолчанию. Сохранённая серия из десяти сценариев дала восемь
ответов `openai` и два честных пустых результата без вызова модели; все машинные
проверки прошли. Явный маршрут: три остановки с возвращением за 72 минуты при бюджете 90.
[Подробности и реальные выводы](docs/LIVE_VALIDATION.md).

### Режим сервера и резервный ответ

| Серверная настройка | Поведение |
|---|---|
| `SERUEN_PROVIDER=openai` | Единый OpenAI API key и явный `OPENAI_MODEL` владельца |
| `SERUEN_PROVIDER=local` | Локальный разбор, поиск и шаблонные карточки без модели |
| `SERUEN_PROVIDER=gemini` | Дополнительный вариант с `GOOGLE_API_KEY` и `GEMINI_MODEL` |
| Провайдер не задан | OpenAI при наличии его ключа, иначе Gemini при наличии Google key, иначе локальный подбор |
| `SERUEN_DEMO=1` или CLI `--demo` | Принудительный локальный режим |

Для дополнительного Gemini каталог показывает `make gemini-models`. Переключение
провайдера выполняет владелец в `.env`, затем перезапускает сервер. Посетителям
настройки подключения не показываются.


OpenAI выделяет старт из запроса, а затем при генерации получает до восьми найденных
кандидатов. Фильтры предпочтений, проверка координат, бюджет и расчёт маршрута выполняются
на сервере приложения. Объяснения строятся по полям POI, а идея
действия модели проходит консервативный фильтр и получает условную формулировку.
Это не полная проверка фактов: условия на месте нужно уточнять.

При сбое сети, отсутствии настроек, лимите или невалидном ответе работает
`retrieval-template`. Приложение не переключается само на другую модель.
Один процесс допускает до двух одновременных запросов OpenAI и до 30 запусков запроса
за минуту, ограничивает вывод 3 000 токенами и не делает автоматических повторов.
Текст пользователя ограничен 2 000 символами. Для публичного развёртывания нужен общий
контроль нагрузки на уровне размещения. Текущий `make run` слушает только `127.0.0.1`; сайт ещё не опубликован.

## Что учитывает поиск

- Стартовую точку, местное время Астаны, бюджет и возвращение к старту.
- Явно выбранные категории, помещение или улицу, ребёнка и размер группы.
- При требовании доступности оставляет только `wheelchair=yes` из OSM.
- Исключает закрытые места и места, которые закроются к приходу или во время посещения,
  когда часы позволяют это рассчитать. Неизвестные часы сохраняет с предупреждением.
- Для парков, садов, площадок и мемориалов без расписания может пояснять неизвестные
  условия доступа вместо часов заведения. Это не подтверждает свободный или круглосуточный
  вход; статус остаётся `unknown`. Заполненное непонятное расписание не скрывается.
- Тишину и розетки использует как пожелания. Без подтверждения в данных не обещает их.
- По желанию запрашивает погоду Open-Meteo и повышает подходящие места в ранжировании.

## RAG и маршрут

Конвейер: определение и подтверждение старта, локальные фильтры POI, BM25 и контекстный скоринг,
до восьми кандидатов, выбор до трёх карточек, проверка маршрута.
CLI и Streamlit вызывают одну функцию `seruen.cli.advise()`.

Радиус зависит от бюджета, минимального планового посещения и запаса в пять минут. Пешая оценка использует
4,2 км/ч и коэффициент 1,3 к прямому расстоянию. Дорога занимает не более 45% бюджета.
При расширении радиуса ограничения по времени и явным требованиям сохраняются.

Маршрут перебирает порядок и подмножества до трёх остановок. Он учитывает переходы,
возврат, посещения и запас. Если две остановки не помещаются, маршрут не предлагается,
а карточки остаются отдельными вариантами. Линии на карте показывают порядок посещения:
граф улиц, переходы, ограждения и состояние тротуаров пока не учитываются.

Подробнее: [архитектура](docs/ARCHITECTURE.md).

## Собственный автоматически собранный датасет

Снимок OSM от **19 октября 2026, 19:20 Asia/Almaty**. Это собственная автоматизированная
сборка открытых данных, а не проверка заведений на месте.

| Показатель | Значение |
|---|---:|
| Мест после нормализации | 1 171 |
| Элементов в исходном ответе | 1 232 |
| Удалённых дублей | 61 |
| С заполненными часами | 317 (27,1%) |
| С `wheelchair=yes` | 41 |
| Названий, присвоенных проектом | 261 |
| Описаний из Wikipedia | 14 |

Категории: рестораны 385, кафе 302, детские площадки 262, достопримечательности 66,
ТЦ 51, парки 39, спорт 24, театры/кино 24, музеи 10, библиотеки 8.
Полная статистика: [`data/quality_report.json`](data/quality_report.json).

`collect/overpass.py` запрашивает bbox Астаны `(51.02, 71.25, 51.25, 71.65)` у трёх
зеркал с повторными попытками. Неполный ответ API с ошибкой не принимается.
Сырой JSON, запрос, дата и SHA-256 сохраняются. `collect/normalize.py` приводит поля к
схеме и удаляет близкие одноимённые записи. Безымянные площадки получают служебные
названия с явной пометкой. Признак помещения может выводиться из типа объекта.

Все сборщики используют стандартную библиотеку Python. Пересборка сохранённого OSM
снимка не требует сети. Для проверки текущего комплекта:

```bash
make verify-data
# или python3 -m seruen.collect.verify --json
```

Проверка сверяет хеши обоих исходных файлов, идентификаторы и нормализованные поля,
источники и статистику. Новый сетевой сбор выполняется отдельно:

```bash
make data       # обновит снимок и data/pois.json
make enrich     # необязательные описания Wikipedia, нужен интернет
make scenarios  # обновить реальные выводы после изменения данных/логики
```

Обновление OSM может изменить числа и рекомендации. Wikipedia-описания имеют ссылки
на статьи, но текущий снимок не хранит их ревизии. Полное повторение сетевого обогащения
побайтно не гарантируется. Перед обновлением сохраняйте прежний комплект данных.

Посетители работают без аккаунтов. Приложение не записывает постоянную историю запросов:
последние пять ответов находятся в памяти отдельной сессии Streamlit. При размещении
на сервере владельца точные координаты, текст и фильтры обрабатываются на этом сервере.
Панель данных показывает координаты с тремя знаками, погода получает два знака.
Настроенный внешний провайдер получает текст, контекст и карточки с расстояниями,
без отдельного поля координат пользователя. Числовые координаты в тексте фильтруются,
но адрес или название места всё ещё могут раскрывать положение. Photon получает короткую
поисковую фразу места и IP серверного соединения. Его кэш хранится только в памяти
процесса до 24 часов, максимум 512 фраз. Серверный ключ
не отправляется в браузер. Подробности: [приватность](docs/PRIVACY.md).

## Проверка и материалы для сдачи

- `make check` проверяет офлайн-тесты, Ruff и целостность данных. Проверка настроек не вызывает модель.
- [Тестовые сценарии](docs/TEST_SCENARIOS.md): пять ситуаций из брифа, EN/KK, проверка
  ограниченного бюджета, явного маршрута и старта у Ботанического сада.
  Десять сохранённых офлайн-выводов с фиксированным временем; все проверки прошли.
- [Реальное подключение модели](docs/LIVE_VALIDATION.md) и [полный live-прогон](docs/live/TEST_SCENARIOS.md):
  сохранённая серия из восьми ответов модели и двух пустых наборов кандидатов без нарушений проверяемых ограничений.
- Прогон сценариев с реальной моделью: `.venv/bin/python tools/gen_test_scenarios.py --live --output-dir docs/live`.
  Обычный `make scenarios` всегда использует локальный режим.
- [Сценарий видео на три минуты](docs/DEMO_SCRIPT.md).

Ограничения: часы заполнены только у 27,1% POI, сложные и праздничные расписания могут
получить статус `unknown`. Наличие часов не означает проверку на месте. Нет данных о
занятости столов, билетах, очередях, безопасности ночью, тротуарах и времени регистрации
на рейс. В сценарии аэропорта программа может честно не найти подходящих мест.
